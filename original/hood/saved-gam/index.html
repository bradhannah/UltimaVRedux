SAVED.GAM byte map

This describes the DOS SAVED.GAM block and companion SAVED.OOL object lists. Offsets are hexadecimal and sizes decimal. Multibyte quantities are little-endian. Allocation boundaries are substantially established; not every saved working field has a complete portable interpretation or a verified malformed-input contract. Redux native snapshots use a separate schema and must not use these offsets.

File boundary and roster addressing

SAVE-0001Original: EstablishedRedux: Matches

The standard saved block is 4,192 bytes (0x1060), covering offsets 0x0000 through 0x105F. The initial two bytes are an allocated boundary field, not a verified magic signature. The excluded ending boundary begins at 0x1060. This establishes the written block length, not every historical loader's response to truncation or trailing bytes.

Sixteen character records begin at 0x0002, each 32 bytes:

character_offset(index) = 0x0002 + index * 32       # index 0..15

Redux's decoder requires the standard block length. Normal numeric values are interpreted by field; little-endian storage does not make every field unsigned.

The three two-byte character quantities are signed 16-bit fields in the reviewed layout; normal HP and experience are nonnegative. Negative/corrupt interpretation is not inferred here. Empty equipment is 0xFF; item zero remains valid.

Active members occupy a packed prefix. Recruitment marks a companion active and swaps its record into that prefix. Inn separation records the location and moves the character out of the prefix. Common marker values are zero for active, a small-map location for inn residence, 0x7F for execution, and 0xFF for unrecruited. The stored armor byte is real data, not padding; its complete relationship to effective protection is a separate equipment question.

The offsets are established. Their complete reload semantics are not: a contiguous memory save can contain temporary process state as well as durable gameplay. Do not infer native snapshot fields from these names or silently discard unknown bytes when preservation is required.

Each schedule has three action bytes, three X, three Y, three level, and four time bytes. Each NPC status has eight 16-bit values, including an explicit object-list association. Path indexes are signed integer indexes, not saved machine pointers; the pause region is 64 bytes, not 64 integer elements. The complete interpretation of every bit and transient status remains incomplete.

Object records and the companion object-list file

SAVE-0006Original: EstablishedRedux: Matches

An object record's eight bytes are base identity, displayed shape, X, Y, level, contextual number, animation state, and miscellaneous state. Identity and display frame are distinct. The contextual number can represent contents, quantity, durability, or another category-specific value; it is not universally HP. Outside combat, slot zero represents the party, including a boarded vehicle. Ordinary NPC association is stored separately in NPC status data.

SAVED.OOL contains two 256-byte lists: Britannia, then Underworld. When one large world is active, its current list in SAVED.GAM supersedes the potentially stale matching companion half. The other half remains the inactive world's list. Town and dungeon saves retain both halves. Redux requires the exact 512-byte companion for player-facing legacy import and explicitly resolves this ownership boundary.

Effect slots and initialization boundaries

SAVE-0007Original: EstablishedRedux: Unverified

The shared global effect/item slot can hold Protection, Negate Magic, Time Stop, Quickness, charm, or the Amulet/Crown/Badge item codes. Duration 255 is exempt from ordinary countdown. Magic-light and torch-light counters are separate. Action spell/magic flags are not extra global active-effect slots. This is not a claim that every persistent magical condition uses one slot.

Character creation loads INIT.GAM, changes selected Avatar fields, and writes the standard block. Allocation alone does not establish a default value for every field or every shipped template. Redux's native state deliberately has its own semantic schema; only explicitly converted legacy fields become authoritative, with preservation/default warnings handled by the import boundary.
